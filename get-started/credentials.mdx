Before you can make your first API call, you need an API key. Paybyrd uses API keys to authenticate every request and to determine whether you are working in test mode or live mode.

## Request your credentials

To get started, request credentials from your Paybyrd point of contact.

<Steps>
  <Step title="Contact your Account Manager">
    Reach out to your dedicated Account Manager at Paybyrd and ask for sandbox (test) credentials. They will provision an API key tied to the test environment.
  </Step>
  <Step title="No account yet?">
    If you don't have an account, contact the Paybyrd sales team at [sales@paybyrd.com](mailto:sales@paybyrd.com). They will get you set up and assign you an Account Manager.
  </Step>
  <Step title="Retrieve your API key from the Backoffice">
    Once your account is provisioned, log in to the Paybyrd Backoffice and navigate to the **Developer Menu** to view and manage your API keys.
  </Step>
</Steps>

<Note>
  You can view and manage all your API keys — both test and live — in the **Developer Menu** inside the Paybyrd Backoffice.
</Note>

## Test mode vs. live mode

The API key you use determines which mode your request runs in:

- **Test API key** — requests run in the sandbox environment and never interact with real banking networks or charge real funds.
- **Live API key** — requests run in the production environment and process real payments.

You do not need to change endpoints or request structure to switch between modes. Simply swap the API key.

## Authenticate your requests

Pass your API key in the `x-api-key` header on every request. There is no other authentication step required.

```bash
curl --request POST \
  --url https://gateway.paybyrd.com/api/v2/payment \
  --header 'x-api-key: YOUR_API_KEY_HERE' \
  --header 'Content-Type: application/json' \
  --data '{
    "type": "Card",
    "amount": "10.00",
    "currency": "EUR",
    "orderRef": "ORDER-001"
  }'
```

Replace `YOUR_API_KEY_HERE` with the API key you retrieved from the Backoffice. Any request sent without a valid `x-api-key` header will be rejected.
